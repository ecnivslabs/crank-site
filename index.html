The argument

Extending by configuration is not the same as adapting.

Plugins and MCP servers let you attach more of the same kind of thing to a harness that otherwise stays fixed. Someone still has to notice the gap, write the extension, and wire it in by hand, every time, for every harness that needs it.

Crank closes that loop itself. It watches its own behavior, writes a replacement when a fixed tool or a fixed interface is the wrong shape for the work, checks it against a real compiler, runs it once in a throwaway copy of the session to see what breaks, and only then lets it touch anything real. The same pipeline that builds a new tool also rewrites the interface you're reading it through and reconfigures how the session itself runs.

64%
fewer fixed-overhead tokens per turn than eager-loading every tool and skill: a single-domain session only pays for what it uses.

It tunes its own loop to the work

The read, plan, edit, verify cycle isn't fixed. A flaky-test hunt wants verification after every change; a broad refactor wants it batched at the end. Crank rewrites the shape of its own loop for the kind of task in front of it, gated and trial-run the same as anything else.
